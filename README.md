# Klyvo — AI Video Studio

Мобильное приложение на Expo SDK 54 и Fastify API для генерации видео и картинок через [fal.ai](https://fal.ai). Интерфейс работает в Expo Go, а готовые файлы сохраняются в библиотеке Klyvo и системную галерею телефона.

## Запуск в Expo Go

Телефон и компьютер должны находиться в одной Wi‑Fi сети.

Первый терминал:

```powershell
cd C:\mobileapp
pnpm install
pnpm db:generate
pnpm db:seed
pnpm api
```

Второй терминал:

```powershell
cd C:\mobileapp
pnpm mobile
```

Отсканируйте QR-код приложением Expo Go. В режиме разработки мобильный клиент автоматически берёт LAN-адрес компьютера из адреса Metro и подключается к API на порту `4000`.

Вход: зарегистрируйте аккаунт прямо в приложении или нажмите «Продолжить без регистрации» — гостю
выдаётся отдельный аккаунт, привязанный к устройству (`POST /auth/guest`), поэтому гости не делят
одну библиотеку и один кошелёк. Демо-аккаунт `demo@klyvo.local / Demo123!` остаётся только в сиде
и больше не подставляется в форму входа.

Если порт `4000` занят старым процессом:

```powershell
Get-NetTCPConnection -LocalPort 4000 -State Listen | Select-Object OwningProcess
Stop-Process -Id <PID>
pnpm api
```

## Генерация

Реализованы параметры:

- первый и необязательный последний кадр;
- 480p, 720p, 1080p и 4K — набор зависит от модели;
- Smart, 21:9, 16:9, 4:3, 1:1, 3:4 и 9:16 — набор зависит от модели;
- длительность от 3 до 15 секунд;
- `Build Quantity`: от 1 до 8 отдельных вариантов;
- генерация со звуком и без звука;
- стили и движение камеры как инструкции внутри промпта;
- картинки: качество low / medium / high и правка загруженного изображения.

После Generate API сразу создаёт одну или несколько записей со статусом `QUEUED`, возвращает
управление приложению и ставит задачу в очередь fal.ai в фоне.

Фоновый воркер API (`startGenerationWorker`) каждые `GENERATION_POLL_SECONDS` секунд сам догоняет все
незавершённые генерации: скачивает готовое видео, списывает кредиты и создаёт запись `Video`. Из-за
этого ролик доходит до конца даже при закрытом приложении. Генерация, зависшая дольше
`GENERATION_TIMEOUT_MINUTES`, помечается ошибкой, а зарезервированные кредиты возвращаются на баланс.

## Вход

Только личный аккаунт: регистрация по email и паролю. Гостевой вход и эндпоинт `POST /auth/guest`
удалены — библиотека, кредиты и публикации требуют настоящего пользователя.

## Модели

Реестр моделей живёт в `packages/shared` (`generationModels`) вместе с адресами моделей у fal.ai.
`GET /models` отдаёт список с признаком `connected` — приложение показывает выпадающий список на
экране создания и всегда пишет, какой моделью вы генерируете. Выбранная модель сохраняется в
`Generation.modelId` и видна на экране результата, в том числе у чужих работ из ленты.

| Модель | Что делает | Форматы кадра | Качество | Адрес у fal.ai |
| --- | --- | --- | --- | --- |
| Kling 3 Standard | видео | 16:9, 9:16, 1:1 | 720p | `fal-ai/kling-video/v3/standard/*` |
| Kling 3 Pro | видео | 16:9, 9:16, 1:1 | 1080p | `fal-ai/kling-video/v3/pro/*` |
| Kling 3 4K | видео | 16:9, 9:16, 1:1 | 4K | `fal-ai/kling-video/v3/4k/*` |
| Seedance 2.0 | видео | все | 480p–4K | `bytedance/seedance-2.0/*` |
| Seedance 2.0 Fast | видео | все | 480p, 720p | `bytedance/seedance-2.0/fast/*` |
| GPT Image 2 | картинки | Smart, 16:9, 4:3, 1:1, 3:4, 9:16 | low/medium/high | `openai/gpt-image-2` |

Возможности проверяются по модели, а не по режиму: три уровня Kling 3 отличаются только качеством,
у GPT Image 2 нет ни длительности, ни звука. Смена модели сама подстраивает несовместимые параметры,
а сервер повторно проверяет их и возвращает 400 с указанием поля.

Обложек fal.ai не отдаёт: для ролика сервер вырезает кадр на первой секунде через ffmpeg,
для картинки обложкой служит она сама.

## Промпт

Перевод **автоматический и серверный**: перед отправкой в модель `dispatchGeneration` переводит
промпт на английский через DeepSeek (`temperature: 0`, дословно) и сохраняет результат в
`enhancedPrompt`. Пользователь ничего не нажимает и перевода не видит — в библиотеке и ленте остаётся
его исходный текст. Если перевести не удалось, запрос уходит как есть и генерация не ломается.
Без `DEEPSEEK_API_KEY` mock-провайдер возвращает текст без изменений.

## Лента

Главная вкладка — двухколоночная кладка (`KlyvoMasonry`) с плитками разной высоты. Высота считается
по формату генерации (`generation.aspectRatio`), а не по `width`/`height` из ответа провайдера:
Провайдер не всегда возвращает размеры кадра, и запасные 1280×720 превращали вертикальные ролики в
горизонтальные. Тот же формат теперь используется и при сохранении видео в базу.

Компонент сам считает положение каждой плитки и включает воспроизведение только у тех, что попали в
экран (не больше шести плееров одновременно); остальные показывают превью, и плеер для них не
создаётся. Больше шести не ставим осознанно: у iOS предел одновременных аппаратных декодеров H.264
около четырёх-шести сессий, за ним плитки чернеют или уходят в программное декодирование.

Вместо лишних плееров работает **зона прогрева**. Полоса запуска несимметрична и следует за
направлением прокрутки: по ходу движения она шире на треть экрана, поэтому плитка начинает играть
ещё до полного появления, а позади — узкая, и пройденные ролики освобождают плеер сразу. Дальше по
ходу движения на полтора экрана вперёд идёт прогрев: там плееры не создаются, но подтягиваются
превью и первые 512 КБ ролика (`moov` лежит в начале файла благодаря `+faststart`), поэтому к
моменту, когда плитка доезжает до экрана, старт мгновенный. При прокрутке вверх всё работает
зеркально. `surfaceType="textureView"` обязателен: на Android `surfaceView` в скролле со
скруглениями рисует чёрный прямоугольник. Если источник видео недоступен, плитка показывает
«Видео недоступно» вместо чёрного квадрата.

Звук выключен по умолчанию и переключается в шапке. Снизу закреплена строка создания: левый круг
прикрепляет кадр из галереи (файл сразу уходит на сервер и попадает в черновик экрана «Создать»),
`+` открывает полный экран создания, стрелка запускает генерацию из шторки с показанной ценой.

Шапка прозрачная, без подложки: слева кнопка бокового меню (`KlyvoDrawer`), справа звук и баланс.
В меню переключаются разделы ленты — «Генерация видео» и «Генерация изображений» (заготовка под
отдельную ленту картинок со своими моделями).

Вкладка ленты остаётся смонтированной при переходе на другие вкладки, поэтому плееры замирали на
паузе и не возобновлялись при возврате. Через `useFocusEffect` при уходе с ленты плитки снимают
плееры целиком, а при возврате создают заново и сразу играют — заодно на чужой вкладке ничего не
буферизуется.

В ленту попадают только работы, файл которых сохранён у нас (`videoStorageKey`). Ссылки fal.ai
живут ограниченное время, и без своей копии видео однажды перестаёт открываться — такие записи
в ленте не показываются.

Открытое из ленты чужое видео не выдаётся за своё: `GET /videos/:id` возвращает `mine` и `liked`,
и экран показывает автора, модель, лайк и жалобу вместо удаления, публикации и повторной генерации.

Демонстрационные ролики из сида больше не создаются. Ранее засеянные удаляются командой:

```powershell
pnpm db:remove-demo
```

## Скорость загрузки медиа

Четыре вещи, из-за которых лента грузилась долго, и что с ними сделано.

**Превью весили 1.7 МБ.** Провайдер отдаёт последний кадр в полном разрешении, а плитке нужно
~180 точек ширины. Страница из 12 карточек тянула больше 20 МБ ради картинок. Теперь маршрут
`/media/videos/:id/thumbnail` при первом обращении делает уменьшенную копию (`sharp`, до 640 px,
качество 72) и кладёт её рядом с оригиналом как `<key>_preview.jpg`; дальше отдаётся готовый файл.
На реальных кадрах: 2611 КБ → 25 КБ, 2957 КБ → 26 КБ, 1241 КБ → 19 КБ. `sharp` подключается
динамически — если пакет не установлен, отдаётся оригинал и в лог уходит предупреждение, API не
падает.

**Медиа читались в память целиком.** Прежний маршрут собирал весь файл в `Buffer` на каждый запрос,
включая каждый Range, — для ролика на 35 МБ это 35 МБ аллокаций на запрос, и так для каждой из
плиток. Теперь и локальное хранилище, и S3/R2 умеют `open(key, range)` и `size(key)`, а маршрут
отдаёт поток нужного отрезка.

**Кэш не работал.** Было `Cache-Control: private, max-age=3600`. Содержимое по адресу с id никогда
не меняется, поэтому теперь `max-age=31536000, immutable` плюс `ETag` и ответ `304` — при повторном
открытии ленты превью не скачиваются заново.

**Плееры создавались на лету при прокрутке.** Одновременно живёт до четырёх плееров (было шесть), и
видео стартует только если плитка задержалась на экране дольше 260 мс — пролетающие мимо карточки
плеер не создают. Буфер уменьшен: на Android по умолчанию плеер набирает 20 секунд вперёд, то есть
почти весь файл; в ленте стоит `preferredForwardBufferDuration: 3` и `minBufferForPlayback: 0.5`.
Превью соседних плиток подгружаются заранее через `Image.prefetch`.

### Отдача медиа мимо сервера

Ключевое для хостинга с оплатой по ресурсам (Railway, Fly и подобные). Если хранилище умеет отдавать
файлы напрямую, приложение получает ссылку **прямо в хранилище**, и байты видео вообще не проходят
через API — сервер отвечает только JSON.

Включается настройкой публичного домена бакета:

```text
STORAGE_MODE=s3
R2_BUCKET=<имя>
R2_PUBLIC_BASE_URL=https://media.вашдомен.ru
```

Без `R2_PUBLIC_BASE_URL` (и в локальной разработке) медиа идёт через `/media/videos/:id/...`, то есть
сервер скачивает файл из хранилища и переливает клиенту. Для разработки это удобно, для продакшена —
двойной трафик и лишний процессор.

Поэтому уменьшенное превью и облегчённая копия **готовятся заранее** фоновым воркером и хранятся как
отдельные объекты (`thumbnailPreviewStorageKey`, `previewStorageKey`). Генерация «по требованию» в
медиамаршруте осталась только запасным путём для локального режима: на прямую ссылку в хранилище
маршрут не вызывается вовсе.

### Облегчённые копии для ленты

Главная причина медленной ленты — вес самих роликов: 1080p на десять секунд весит до 33 МБ, и три
такие плитки это ~47 МБ. По Wi-Fi они не проигрываются плавно ни на каком буфере.

Фоновый воркер делает копию для ленты через `ffmpeg-static`: **720p по короткой стороне, `-crf 23`,
профиль `main`**, без звука, `-movflags +faststart` (moov в начале файла, чтобы воспроизведение
начиналось без полной загрузки). Ключ хранится в `Video.previewStorageKey`.

Настройки подобраны замером на реальном ролике 16.4 МБ:

| Настройки | Размер | Легче оригинала | Время |
|---|---|---|---|
| 480p crf30 | 0.10 МБ | 157× | 6.6 с |
| 640p crf26 | 0.34 МБ | 48× | 6.4 с |
| 720p crf26 | 0.44 МБ | 37× | 9.6 с |
| **720p crf23** | **0.82 МБ** | **20×** | **10.6 с** |

480p/crf30 давал видимую потерю качества: плитка шириной ~180 точек на экране с тройной плотностью
требует около 540 пикселей. 720p/crf23 закрывает это с запасом и всё равно легче оригинала в 20 раз.

Копия готовится **сразу при публикации** (`requestFeedPreview`), а не в порядке очереди: иначе первые
секунды после публикации лента отдавала бы тяжёлый оригинал — из-за этого новые ролики плохо
запускались. Воркер догоняет остальные, свежеопубликованные обрабатываются первыми.

Если `ffmpeg-static` недоступен, лента отдаёт оригиналы и продолжает работать.

### Длинная лента

Позиция и высота каждой плитки известны заранее, поэтому `KlyvoMasonry` рисует только те, что
попадают в окно вокруг экрана: один экран выше и полтора ниже (`overscanAbove` / `overscanBelow`).
Остальные не существуют как компоненты — расход памяти не зависит от того, пролистали вы двадцать
роликов или две тысячи. Контейнер имеет заранее посчитанную высоту, поэтому полоса прокрутки и
позиция остаются верными. Окно пересобирается не на каждый кадр, а раз в ~48 точек прокрутки.

Данные тоже подгружаются постранично, по 12 записей, курсором — весь список никогда не запрашивается
целиком.

## Хранение и публикация

- SQLite сохраняет генерации и видео после перезапуска.
- Готовый MP4 и уникальный последний кадр каждого ролика копируются в локальное хранилище API или R2.
- Медиамаршрут поддерживает HTTP Range для воспроизведения.
- Кнопка «В галерею» скачивает MP4 и сохраняет его через `expo-media-library`.
- Видео приватно по умолчанию. В ленту попадают только явно опубликованные ролики со статусом `PUBLIC`.
- Публикацию можно отменить из приложения: `POST /videos/:id/unpublish`.
- `DELETE /me` полностью удаляет аккаунт со всеми генерациями, видео, публикациями и файлами.

## Бренд

Название приложения, scheme, slug, bundle identifier, Android package, UI, splash и store-иконки используют бренд Klyvo. Готовые файлы находятся в `apps/mobile/assets/brand`.

## Основные команды

```powershell
pnpm api             # Fastify API
pnpm mobile          # Expo SDK 54
pnpm db:generate     # Prisma Client
pnpm db:seed         # демо-аккаунт и демонстрационные видео
pnpm typecheck       # TypeScript во всех workspace
pnpm lint            # ESLint
pnpm test            # unit и API integration tests
```

Swagger доступен по адресу `http://localhost:4000/docs` после запуска API.

## Проверка

```powershell
pnpm typecheck   # без ошибок
pnpm lint        # без ошибок
pnpm test        # unit + API integration
```

Тесты принудительно включают mock-провайдер и не запускают платные генерации fal.ai.
`pnpm test` пересоздаёт отдельную базу `apps/api/prisma/test.db` (`prisma db push --force-reset`);
`dev.db` при этом не затрагивается.
